# 从视频契约生成 New API 视频插件

在 **设置 → 视频模型契约** 中，点击某份契约右侧的 **生成 New API 插件** 图标。查看或编辑契约时，也可以使用弹窗底部的同名按钮。

使用 **从文档生成**（上传文件或文档链接）时，可打开 **生成 New API 插件** 开关。该开关每次打开文档生成窗口时默认关闭：关闭时只生成契约草稿；开启时，草稿生成完成后进入插件配置与下载流程。核对自动填写结果并补齐缺失项后，点击 **生成并预览**，无需先发布契约。关闭插件窗口会返回契约审核列表。

插件配置会自动填入文档与契约已有的信息：模型列表、字段映射、创建/查询路径、结果字段和下载方式；正文明确声明的 Base URL、鉴权方式及自定义请求头保存在契约 `provider` 中，保存、导出、导入后再次生成插件仍会读取。文档地址不能直接当作 API 地址；未知地址留空，未知鉴权需要补选，不能默认认定 Bearer 或无需鉴权。文档生成会核验供应商配置的原文引文。插件标识按模型与协议稳定生成，初始版本为 `1.0.0`，不把供应商 API 版本当作插件版本；升级已有插件时保持原插件标识并递增版本。Key 只在 New API 渠道填写。

文档链接支持静态正文、`llms.txt` 索引和 OpenAPI 页面。对于使用 `/api/api-docs/list`、`/api/api-docs/detail` 公开目录协议的动态文档站，系统会从页面引用的同站脚本识别该协议，按目录读取全部视频详情；无需手动替换原页面地址。读取过程不执行网页脚本、不携带用户 Key，也不会请求视频生成端点。脚本最多读取 24 份，每份 1 MiB；文档详情最多 24 份，总读取大小和正文长度仍受文档导入限制。缺失详情、文档访问失败或超限时停止，不生成缺页草稿。其他未支持的动态页面若只有“加载中”或导航，不会作为接口正文进入契约生成，需要提供可直接读取的文档数据链接或上传文件。

已有契约可以单独生成插件：点击列表中某份契约的代码图标，或在查看、编辑契约时使用弹窗底部的 **生成 New API 插件**。批量勾选工具栏不提供插件生成入口；需要多个插件时，分别从各契约入口生成。

- 列表入口使用该契约的已发布版本。
- 编辑入口使用当前编辑快照，不会自动保存或发布契约。
- 文档生成流程使用生成草稿的快照；一份文档拆分出的多份契约分别配置和生成插件。
- 契约文档分析后会校验每个模型的创建/查询、能力参数、轮询和下载文档引文，并对每个模型的每种生成模式执行代表性请求干跑。引文缺失、必填参数无法映射、能力无法表达或文档冲突时，会逐项显示原因并标为“契约待确认”，不能标成契约初审通过。即使打开插件生成开关，也会先停在审核页面，需核对并修正后从契约编辑入口生成插件。干跑不是上游联调，也未穷举所有参数组合。
- 分析模型同时收到完整输出 Schema 和结构化响应约束，两者来自同一定义。未声明的 `extra_body` 等属性会被严格拒绝并反馈修正，不会静默删除或透传供应商扩展参数。请求示例中的完整模型 ID 按原样保留，包括普通空格；文档页面的 slug 不会替代真实模型 ID。
- 任一契约校验或干跑失败会把上一轮 JSON 与具体错误反馈给模型，最多修正三轮；修正保留原始文档和此前有证据的字段。插件生成后会在浏览器 Worker 中加载生成的 JavaScript，用后端提供的各模式测试样本模拟请求、状态和视频地址，检查创建、轮询、用量及下载流程。
- 插件 Worker 拦截 fetch 且 15 秒超时，会终止卡住的测试。该本地干跑不会访问供应商、创建视频任务或读取/导出密钥；它也不等同于 New API 运行时沙盒测试，部署前仍需核对供应商文档并在测试渠道联调。
- 干跑通过后才可预览、复制和下载带中文注释的单文件 `.js`。上传与激活仍在目标 New API 管理后台操作。

## 生成配置

| 配置 | 说明 |
| --- | --- |
| 插件标识 | 最多 30 个字符，渠道绑定用的稳定标识，例如 `my-video-provider`；升级时保持不变 |
| 插件版本 | 例如 `1.0.0`；源码发生变化时递增，不能用同一版本覆盖不同源码 |
| 供应商 Base URL | 选填。填写时作为插件的默认 HTTP(S) 上游地址，规范化后最多 191 个字符，不包含密钥、查询参数或具体创建接口；留空时不声明 `meta.baseUrl`，在 New API 渠道中填写实际地址 |
| 上游鉴权 | 支持 Bearer、自定义 Key 请求头或无需鉴权；实际 Key 在 New API 渠道填写 |
| 完整模型 ID | 每行一个，必须匹配当前契约；模型通配符需展开成真实模型 ID |
| 视频下载方式 | 必须按供应商接口选择，不能用中转的 `/content` 路由推断供应商实现 |
| 上游视频地址字段 | 查询响应中的 JSON 路径，例如 `video_url` 或 `data[0].url`；界面占位内容不会自动写入 |

## 三种下载方式

1. **查询签名地址后下载**：先用渠道 Key 查询最新任务结果，再向返回的签名地址发送 `credentialless: true` 的 GET/HEAD 请求。下载请求不携带 Key，适用于 CDN 签名视频地址。
2. **请求上游 content 接口**：访问契约的产物路径，使用选定的上游鉴权方式。带凭据的下载如果跨域重定向，New API 会拒绝；这种供应商应改用签名地址模式。
3. **查询结果地址并携带 Key 下载**：每次查询最新结果地址，带渠道 Key 下载。目标域名必须属于渠道域名或契约明确配置的精确允许域名，不支持通配域名。

例如，当前 Dramaya Grok 接口的 Base URL 为 `https://video.dramaya.us`，使用 Bearer 鉴权，选择“查询签名地址后下载”，结果字段填写 `video_url` 和 `data[0].url`。插件中的 `ctx.apiKey` 用于查询任务；最终签名视频请求不携带该 Key。

## 对外视频接口

生成的插件只声明 `openai_video` 视频协议，不声明供应商原生路由：

- `POST /v1/videos`：提交生成任务。
- `GET /v1/videos/{id}`：查询任务。
- `GET /v1/videos/{id}/content`：下载视频。
- `HEAD /v1/videos/{id}/content`：读取视频响应头。

这些是 New API 宿主的协议路由；请求体仍使用契约配置的字段，不自动转换 `seconds`、`size` 等参数别名。宿主通用任务管理接口不属于插件额外声明的视频协议。

## 能力与限制

生成器保留每个模型的画幅、时长、清晰度、素材范围、提示词长度及条件规则，支持嵌套请求字段和响应 JSON 路径。未声明字段、错误参数类型、未知任务状态会明确报错。

支持 JSON 素材 URL 和契约明确声明的 multipart 上传。文件通过 New API 宿主的 `files[].ref`、`bodyType: "multipart"` 和 `parts[].fileRef` 转发，不在插件中读取文件字节；具名字段使用 `transport.multipart_fields`，重复文件与 URL 混传分别按契约校验。无法唯一判断素材角色的统一文件字段会在干跑时报错。Ark、Volcengine 的专用请求转换、AutoDL 工作流仍需要专用适配。依赖动态路径的接口需要先在契约中明确创建与查询路径；JWT/OAuth 签名等特殊鉴权也不能当作普通 Bearer Key 使用。

仅提供请求时长和清晰度作为用量字段，不内置价格，也不推测供应商实际费用。实际定价、任务轮询和超时遵循 New API 配置。生成器不自动添加供应商文档未声明的幂等请求头。

生成接口为管理员专用的 `POST /api/admin/video-model-contracts/newapi-plugin`，接收 `contract` 和 `options`，返回 `filename`、`source`、`warnings`。不会改变已保存契约、渠道或生产 New API 插件。

## 附加参数与审核

`capability.parameters` 为模型分别声明参数名称、中文标签、上游字段、类型、必填、默认值、枚举、数值范围和适用模式。例如 `seed` 是随机种子，`prompt_enhance` 是提示词增强开关，`callback_url` 是上游通知地址；未设置的可选参数不发送，`0` 和 `false` 保留。必填 `prompt_expansion_mode` 可以要求用户从 `balanced`、`quality` 中选择，不能把它冒充生成模式。

创作接口通过 `parameters` 对象提交已声明参数。插件对外请求使用契约指定的上游字段。独立的 `aspect_ratio` 可作为附加参数，与必填像素 `size` 分别发送；`seconds_range` 表示连续时长，`max: null` 表示文档未设上限，与 `seconds` 枚举互斥；`request.reference_value_type: "scalar"` 表示单个素材 URL，参考素材合计上限必须为 1。

未配置轮询间隔、超时时，系统分别使用 5 秒、900 秒；这不属于待确认问题。文档审核分别返回阻断问题 `review_issues`、非阻断限制 `limitations` 和配置说明 `notes`。结构化公开目录还会独立核对模型清单和必填字段；超长文档会停止生成，避免截断后假通过。

本地插件干跑核对实际出站 body（包括附加参数、强制值和素材编码），并对 multipart 素材样本检查文件路由。编辑过的草稿不会借插件干跑结果自动重新获得契约初审通过状态。干跑不等同于生产 New API 宿主测试或上游视频实测。

## New API 规范核对

2026-10-23 已核对 QuantumNous/new-api 提交 `33c61a24234aa20cb10e8a644304322c476361de` 的 `docs/plugin-api/v1.md`、`v1.d.ts` 和 `v1.schema.json`。插件仍使用 `apiVersion: 1`。

- 请求地址只取宿主传入的渠道 `ctx.baseUrl`；修改插件默认地址不会迁移已有渠道。本地干跑会使用独立测试渠道地址，检查它覆盖插件默认值的行为。
- `meta.auth` 按配置声明 `api_key` 或 `none`；不读取、透传客户端的网关鉴权请求头。
- 解码返回客户端 `ctx.model`，能力校验与用量按渠道映射后的模型选择；映射为供应商端点 ID 时，使用原模型能力。创建请求只在 body 中发送 `ctx.upstreamModel`，不改写宿主锁定的模型身份。解码可重复执行。
- multipart 使用宿主提供的 opaque 文件引用与 `parts[].fileRef`，不读取文件字节，不设置 boundary。
- New API 对 `unit: "second"` 的用量限制为 3600 秒。生成插件拒绝超过该值的请求；开放范围契约会显示此宿主限制，原契约不会被截断。默认或强制样本超过上限时停止插件生成。
- 数值计费字段的展示标签使用“视频生成单价”，字段本身仍报告请求秒数，不包含价格。
- 查询、下载重定向及 SSRF 检查由宿主处理；HTTP(S) 结果地址按所选鉴权方式生成请求。带凭据下载仍不能跨域重定向。

通用生成器未声明 `upstreams: ["new_api"]`：供应商查询状态、结果字段及原生路径不一定等于另一个网关的响应，不能仅凭相同的 `/v1/videos` 创建路径宣称支持网关级联。当前生成插件绑定“任务插件”渠道。
