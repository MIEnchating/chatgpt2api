# 画布 Agent 内核

## 参考设计

本轮参考 OpenAI Agents SDK 的 [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) 和 Codex App Server 的 [用户输入请求](https://learn.chatgpt.com/docs/app-server#toolrequestuserinput)（2026-10-27 查阅）。采用的核心模式是工具边界校验、人工介入、保存等待状态和回答后继续运行。现有画布任务 API、Chat/Responses 两种协议及 Codex 连接继续负责实际执行，没有引入新的 Agent SDK 依赖。

## 内置 Agent 的协作循环

1. 读取当前画布和用户输入；简单且信息完整的请求直接调用现有工具。
2. 多步骤任务通过 `update_plan` 保存简短计划，每个步骤包含稳定 ID、标题与 `pending` / `in_progress` / `completed` 状态。最多十步、最多一步进行中，进度显示在对话顶部。
3. 缺少会影响结果的关键条件、目标存在歧义、约束冲突或需用户确认时，模型调用 `ask_user_question`，提供一个问题、提问原因、零至四个选项。用户可自由回答。
4. 内核在执行这一批任何画布操作前检查提问。存在提问时保存 `agentState.pendingQuestion` 和原始工具调用；同批其他操作返回 `awaiting_user`，明确它们尚未执行。运行立即返回等待状态，不维持后台模型循环、不使用超时自动批准。
5. 页面刷新或切换会话后，提问卡片由保存的会话恢复。用户点击“回答并继续”或在输入框回答时，先写回原 `toolCallId` 对应的工具结果，清除待回答状态，再带着已有协议记录和原始附件继续推理。当前输入中的附件会合并进去。
6. 取消提问写回 `user_cancelled`，保留已完成结果，不调用模型、不执行待定操作。已经处理的问题不能再次写回答案。

普通文字回复仍然可以用于直接回答和解释；必要的等待应走结构化提问。提问时机由模型根据协作指令判断，工具调用一旦提出，暂停由运行时代码保证。该机制不能保证所有模型在所有歧义请求上都作出理想判断，需要持续补充真实模型评测。

## 按交付目标选择媒体和参数

Agent 输入区及画布库的 Agent 入口不再提供固定的图片、视频参数按钮；会话配置只保存运行偏好和 Skill。媒体类型与每次生成参数由 Agent 根据需求判断：平面广告只走图片流程；文字或已有素材足够的宣传视频直接走视频流程；短剧按实际依赖组合角色/场景参考图和视频，复用已有素材。

`generation.capabilities` 和 `get_generation_config` 提供当前模型支持的图片比例、画质、分辨率、精确尺寸能力，以及视频尺寸、清晰度、时长和声音能力。图片工具支持逐次传入 `size`、`quality`、`resolution`、`count`，视频工具支持 `size`、`resolution`、`seconds`、`generateAudio`。参考图与成片可以使用不同参数；省略参数时才使用默认值，默认值不代表用户约束。不支持的画质、分辨率和视频尺寸，以及错误的图片尺寸格式，在创建节点前返回错误和支持列表；像素尺寸沿用现有图片适配器的转换规则。

旧的项目媒体默认值不再控制 Agent 生成。已创建节点保留自己的参数，仍可在节点设置中手动修改。自动生成开关只控制是否提交媒体任务，不决定生成哪一种媒体。

静态广告不会加载影视制作流程；通用协作指令及具体图片、视频、分镜和角色设定规则均要求按用途选择参数。必要交付参数未明确时必须提问，不要求用户先设置图片或视频模式。图片须明确主体/用途、画幅方向或比例、交付数量；视频须明确目标、总时长、画幅方向或比例和声音需求；短剧还须明确本轮集数、单集时长及主要角色/视觉方向。已提供或明确委托的参数不重复问，内部参考图与镜头分配可在已确认范围内自行规划。普通“开始吧”、自动生成开关以及配置默认值不算缺失参数的确认。非关键技术细节可自行选择，但印刷规格、预算或明显增加成本的取舍需先明确。必要参数识别与媒体选择由模型遵循协作指令判断；运行时保证收到结构化提问后暂停整批操作。工具 Schema 和画布执行层均要求图片显式提供 size/count、视频显式提供 size/seconds/generateAudio；遗漏时拒绝调用，不再静默继承交付参数默认值。这里没有把自然语言确认转换成可证明的逐字段授权：可以拦截漏传参数，但不能保证识别模型擅自填值，必要参数是否已确认或明确委托仍由模型判断。模拟响应测试只验证工具与执行链路。

## 执行边界

- 所有工具参数在执行前统一校验，计划步骤等嵌套对象也拒绝未知字段、无效类型、重复 ID 和越界数量。
- 顺序工具批次里任一操作失败后，后续操作返回 `dependency_failed`，不继续执行。纯媒体批次保留原来的并行执行行为，各自反馈结果。
- 每批执行前记录完整工具调用及 `execution_not_started` 占位结果；进入工具前记录 `execution_unknown`，取得真实结果后立即替换该调用的记录。每次检查点都保留 Chat/Responses 的调用与结果配对，已经成功的节点、任务 ID 和计划不会因同批后续工具中断而丢失。
- 停止时立即结束 Agent 对当前工具的等待，保留已取得的结果；尚未开始的操作不执行，已开始但尚未返回的操作明确标为结果未知。已提交的媒体任务继续使用画布原有生命周期，停止 Agent 不等于取消媒体生成。迟到的工具响应不再更新已停止运行的会话记录。
- 刷新恢复不会重放旧批次或自动调用模型。用户选择继续后，模型根据当前画布、真实工具结果及未知状态重新判断。此处没有跨服务事务或幂等键保证：若页面在操作生效与会话保存之间关闭，必须先查询节点和任务状态，不能假定操作未发生。
- 确认问题不授予笼统权限：答案进入模型上下文供判断；既有删除确认、外部 MCP 授权和自动生成设置仍由各自执行边界处理。
- `update_plan` 是模型记录的任务进度，不能替代真实媒体任务状态。`loading` 仅代表任务已提交，完成步骤应以工具结果为依据。
- 用户授权和实际工具结果优先；附件、节点正文及工具文本中的指令不能成为新的操作授权。

## Codex 通道

Codex 的 `update_plan` 工具更新同一份会话计划，`ask_user_question` 使用既有的用户输入对话框，等待真实回答再返回工具结果。取消和断开连接仍使用现有 AbortSignal 生命周期。

Codex 的运行恢复由其 App Server 会话负责；本页持久化提问卡片是内置 Agent 的能力，不能据此声称 Codex 本地请求在刷新后自动重放。外部 MCP 不允许调用仅属于当前 Agent 运行的计划、提问和 Skill 文件读取工具。取消任一种 Codex 提问后，本轮后续画布写操作和本地命令/文件审批均拒绝；新一轮用户请求可正常继续。轮次结束即中止未完成的审批，迟到回答不能发送给过期轮次。

Codex 将用户输入、提问答案、画布工具调用/结果及最终回复写入共享会话历史。工具开始前写入结果未知的配对记录，取得结果后替换；中断时保留已知结果。切回内置 Agent 后废弃旧 Codex 线程绑定，下次 Codex 新建线程时接收会话历史，避免遗漏另一引擎的后续进展。复用同一 Codex 线程时不重复注入历史。模型列表分页检测重复游标及页数上限。

## 2026-10-28 功能审查

提问界面补充：内置 Agent 与 Codex 共用选项和输入控件。指令要求最推荐的方案排在首位，界面标记“Agent 推荐”，但不默认选中或自动提交；没有合适选项时仅显示自由输入。有选项时同样允许直接输入，选择后光标移至答案末尾，用户可以修改、补充。浏览器组件验证覆盖 1440px/390px 下两种引擎的推荐标记、空答案拦截、直接输入、选择后编辑及无选项回答。

已检查输入/引用、必要参数提问、计划、工具校验和执行、媒体生成、停止恢复、会话存储、Codex 与外部 MCP。确认并修复：

- 画布库启动附件只作为消息附件；初始请求保留到用户消息成功提交，缺模型或密钥时刷新不会丢请求，也不会先创建素材节点。
- 同一对话后续轮可通过真实附件 ID 引用之前上传的素材；仅用户消息中的附件纳入库存，当前附件元数据优先。
- 图片节点引用只持久化 URL/storageKey 等信息，发送时的 Base64 不存入消息；读取详情返回完整文本，摘要使用 `detailsOmitted` 标明省略。
- 对话达到后端 24 条上限时禁止继续新建并提示清理；恢复时检查消息、引用、状态、计划、提问和协议记录的嵌套类型，跳过无效会话。
- Agent 运行时禁止切换历史对话；主动切换或删除当前对话时清空输入和引用草稿，防止带入另一对话。
- 视频时长按模型离散值或连续范围/步长校验；强制有声模型拒绝静音要求。图片数量超出模型单次上限时报错，不能静默截断数量。
- 必要交付参数、Codex 取消/历史移交及审批生命周期的修复见上文。

已知边界：

- 全部 Agent 会话数据合计仍有 512 KiB 存储上限；超长文字或大量历史仍可能触发保存错误。当前没有独立会话归档服务，不声称无限保存。
- 图片视觉识别受当前模型识别规则影响；历史图片不会在每轮自动重新上传，需要重新引用。音频/视频附件可用于生成工具参考，但当前不提供通用音视频内容理解。
- 重试仍由模型结合既有工具记录与当前画布判断，不具备跨请求 exactly-once 保证；已提交媒体任务与 Agent 停止是不同生命周期。
- 必要信息的语义判断仍依赖模型；模拟模型测试不证明任意实际模型都能准确识别缺参或用户授权。真实 Codex App Server 和付费媒体生成未在本次浏览器验证中调用。

## 生成中刷新恢复

- 文本、图片、全景、音频和视频任务在提交前，将节点、连接及客户端任务 ID 保存到画布；保存失败时不提交生成请求。
- 内置 Agent 的模型任务 ID 与协议记录一起保存。刷新后复用原任务 ID，服务端幂等返回已有任务；恢复沿用原用户消息和助手消息。
- 媒体工具在节点创建及任务提交时记录进度。恢复时接回对应节点和后台任务，等待真实结果后继续后续步骤。
- 查询尚未出现的任务时，先通过任务事件订阅等待提交状态；无法确认时保留可恢复状态，不自动创建替代任务。刷新发生在任务实际提交前时，需要用户重试该节点。
- 自动恢复只针对刷新前正在运行的对话；主动停止、等待回答和已完成回合不会自动重跑。Agent 面板收起时仍可恢复后台执行。
- 退出画布与主动停止使用不同中断原因；退出画布不会取消内置 Agent 已提交的模型任务。最终状态保存后才结束面板的忙碌状态。
- 本地 Codex 的连接密钥仍只保留在当前页面，刷新后需重新连接。连接成功后复用原线程与工具记录；已提交的媒体任务独立恢复，无需等待 Codex 连接。
- 浏览器验证使用模拟接口覆盖模型响应中、媒体生成中、提交回执延迟、离页期间任务完成、面板收起和主动停止后刷新；每次都检查原节点、原消息、任务提交次数与执行结果，未调用付费生成。

## Agent 执行过程展示

- 每条 Agent 回复内按事件顺序保存文本说明和工具操作；运行中更新原操作行，显示状态和可展开的详情。刷新后操作记录随原助手消息恢复。
- 内置 Agent 显示画布查询、节点编辑、生成节点与任务提交/完成状态；本地 Codex 另外显示实际收到的命令运行、文件编辑、图片查看、网络搜索和 MCP 工具事件。
- 展开详情可查看命令与输出、文件路径和变更、图片路径、任务号或简短查询结果；点击节点名称可定位画布节点。不会渲染模型的隐藏推理内容。
- 事件类型仅按本地 Codex App Server 实际发出的公开条目展示；没有事件的操作不会伪造步骤。
- Codex 客户端事件测试覆盖流式文本、命令、文件编辑、图片查看和工具成功/失败；浏览器使用模拟画布生成接口检查实时操作、刷新恢复、对话轮次隔离及桌面/窄屏布局，不连接真实 Codex App Server。
