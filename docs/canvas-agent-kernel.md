# 画布 Agent 内核

## 参考设计

内置 Agent 使用 LangGraph 状态图管理模型与工具循环及用户审批暂停和恢复；Go 后端管理身份、模型中转、画布/工作流业务工具、媒体任务和持久化，继续复用现有 Chat/Responses 协议。本地 Codex 继续使用自身 App Server 引擎。

## 执行位置与接口

内置 Agent 的 LangGraph worker 在私有 stdio 子进程中运行，不监听网络端口，也不接收 API 密钥；`internal/service/canvas_agent*.go` 通过 stdin/stdout 提供已认证模型响应和工具结果，并负责工具校验、画布/工作流操作、媒体任务、计划和检查点持久化。worker 负责上下文整理以及问题和删除审批的暂停与恢复。浏览器仅提交请求、展示快照、回答问题和发送停止指令。工具 Schema、中文标签与内置 Skill 提示词统一存放于 `internal/service/canvas_agent_assets/*.json`，Go 和 Codex 前端共用这些定义。

Docker 镜像内含 Node.js 22、固定版本 LangGraph 依赖及 worker；后端按需启动 worker，用户无需单独运行 Agent 容器、开放端口或安装 Node.js。Windows 桌面包包含同一运行时。Linux 独立压缩包提供 worker 和锁文件，首次运行前按包内说明安装依赖。

已认证的 `/api/canvas/agent-runs?project_id=...` 支持：

- `POST`：根据已保存的会话启动或继续执行，保存运行 ID 并立即返回；同一运行 ID 重复提交返回已有状态。
- `GET`：读取最新画布、会话和 `agent_run` 状态。
- `DELETE`：通过 `run_id` 停止当前运行或取消待回答的问题。

Codex 对话通过 `POST /api/canvas/agent-tools?project_id=...` 调用同一套 Go 工具，结果及审核指纹随运行快照返回；画布工具不再在浏览器重复实现。计划、提问、Skill 读取和删除确认保留各自的交互入口。外部 MCP 的 `get_node`、`confirm_script_node` 和六个工作流工具也通过该后端入口调用；外部写操作先经过用户授权，系列提示词另行展示并审核。

`POST /api/canvas/agent-tools/review-answers?project_id=...` 只接收用户界面的回答、会话 ID 和已展示的提示词指纹，模型工具参数中不接受批准字段。批准时验证当前待审节点集合及提示词指纹；修改内容后必须重新审核。拒绝或取消将媒体生成设为暂缓。已有内置 SDK 待回答状态不能被外部工具运行覆盖。

每个用户的每个画布同时只允许一个后台运行。运行上下文独立于 HTTP 请求，关闭页面不会取消执行；画布和对话检查点保存在现有存储中。运行期间允许编辑和保存节点，版本冲突时读取最新快照并合并本地修改；清空、重命名及删除整个画布仍返回 409，需先停止运行。后台保存不切换用户当前打开的项目。

这是单后端进程的执行协调，不提供多副本分布式租约或跨服务 exactly-once 保证。后端重启后，尚未完成的运行标记为 interrupted，等待用户检查后继续；不自动重放未知操作。已提交的媒体任务使用独立生命周期。

## 前端执行视图

前端通过现有 Go 接口消费 LangGraph 运行快照，不在浏览器创建状态图或读取私有检查点。`canvas-agent-panel.tsx` 管理提交、引用、附件与消息队列，`canvas-agent-conversation.tsx` 独立投影对话、推理、工具和来源；共享 AI Elements 组件承接 Conversation、Message、PromptInput、Task、Tool、Plan、Confirmation 与运行状态。

同一会话、同一助手消息对应的 `agent_run.status` 优先于消息中的展示状态，明确区分执行中、等待、中断、停止、失败和成功；排队消息也必须等待当前服务端运行成功。待确认问题只接受真实用户选择或输入，恢复按钮不能代替批准。对话中的 Checkpoint 表示编辑并创建对话分支，不表示 LangGraph 的私有运行检查点。

节点内容同步只更新绑定节点的引用，`source: "attachment"` 的独立上传附件不随同 ID 节点替换或删除而改写。删除节点仅清除相关节点引用的媒体地址与存储引用，保留消息正文及其他引用；未受影响的消息、消息数组和会话继续复用。同步时消息未中断、无处理计时且引用不变，直接保留原消息，不读取或复制正文；输入边界的完整数据校验仍保留。

后端快照只有包含成功的 `arrange_nodes` 操作时才读取旧会话来核对是否首次完成，并只在出现新完成操作时适配画布。普通无正文保存回执、其他工具和未成功的整理操作不为缩放扫描旧聊天；收到的会话及合并结果仍经过完整校验，同一版本的快照也先校验再清除同步错误。

保存回执更新服务端基线时，按会话 ID 和字段值复用旧基线中未变化的字段，只对变化部分与画布数据执行 JSON 深拷贝。正文、协议及状态仅在确实相等时复用已经隔离的旧字段；新增或变化字段独立复制，删除及未定义字段沿用 JSON 保存语义。旧基线只替换、不原地编辑，也不与本地编辑内容建立可变共享引用。

当前文档保存失败时持续显示未保存提示及“重试保存”，重试进行中禁用按钮；只有当前全部修改均已保存才清除错误，旧版本的成功回执不能清除新修改的失败提示。切换文档、重新打开同一项目或卸载后的迟到失败不向新页面发布错误。页面存在未保存修改时，通过浏览器原生 `beforeunload` 提示保护正常刷新或关闭；站内导航使用 React Router 的阻塞能力。当前账号仍有画布权限、画布已加载且存在未保存修改时，菜单跳转和浏览器前进或返回等待最新保存成功，失败则留在原编辑器。新的导航或已离开的编辑器不应用旧保存结果，登录及权限变化仍交给原路由鉴权处理。这不保证浏览器崩溃、强制关闭或用户明确放弃修改后的数据恢复。

Agent 展开且存在会话冲突或正在另存两份对话时，由面板内的冲突提示承接处理入口，普通保存失败浮层暂不重复显示，避免挡住窄屏的“保留两份对话”按钮。保存错误状态与未保存保护仍保留，面板收起或冲突处理结束后继续按实际保存结果展示；普通网络或存储失败仍显示持续提示与重试入口。

重命名当前画布的回执沿用服务端快照合并，不重新打开整个文档；重命名期间的节点与聊天编辑、撤销记录和待保存版本继续保留，低于当前 revision 的回执不能回退已保存内容。项目操作在排队后、保存后及应用回执前核对项目与文档实例；已卸载或重新打开的文档不接收旧操作回执和错误。切换到已知项目时，当前编辑器先保存修改，然后导航到目标地址。由目标编辑器读取并激活项目，避免切换按钮和页面入口分别下载同一份正文。目标加载错误显示在目标地址，支持重新加载。编辑器导入归档后使用新项目地址，刷新按该地址恢复新项目及会话。归档解析后、当前画布保存后及收到导入响应时均检查文档实例，旧操作不能把新页面导航到导入项目。新建和删除继续使用项目操作回执。

脚本工作区仅在打开脚本编辑器时加载，对话成片卡片仅在实际展示已有合并结果时加载。两处使用 React `lazy`/`Suspense` 与共享 LoadingState，在等待期间明确显示状态；空画布和没有成片的聊天不提前加载脚本编辑界面或其 Video.js 依赖。打开后的编辑、保存、素材与成品查看、播放和下载仍沿用原实现，不改变聊天读取或媒体生成行为。

消息底部的复制、编辑与重试继续使用共享复制控件和按钮，通过已有 `data-tooltip` 桥接显示提示，不为每条消息单独创建 Tooltip 根。共享桥接沿用鼠标延迟提示、键盘聚焦提示、Escape/点击关闭与浮层层级；按钮的无障碍名称、禁用规则和操作回调不变，复制反馈仍由共享复制控件处理。

打开画布时，已解码的 JSON 响应通过 `structuredClone` 生成一份可编辑文档，原响应保留为独立服务端基线，不再用 JSON 编码/解码制造完整聊天的中间字符串。引用、轨迹、协议参数、状态与索引均独立，恢复中断消息只修改编辑侧；完整会话校验仍在提交界面状态之前执行。保存回执继续按上述 JSON 保存语义更新基线。

工作流和视频契约通过 `AgentExecutionMonitor` 与 `useAgentExecution` 共用后台恢复观察。新工作流按提交时生成的运行 ID 读取进度；恢复只操作原运行 ID。卸载、关闭和账号变化仅取消观察并丢弃过期响应，显式停止才发送 DELETE，随后重新读取服务端状态。初始读取失败提供重试入口，重复恢复或停止点击不会重复提交。

## 内置 Agent 的协作循环

1. 读取当前画布和用户输入；简单且信息完整的请求直接调用现有工具。
2. 多步骤任务通过 `update_plan` 保存简短计划，每个步骤包含稳定 ID、标题与 `pending` / `in_progress` / `completed` 状态。最多十步、最多一步进行中，进度显示在对话顶部。
3. 缺少会影响结果的关键条件、目标存在歧义、约束冲突或需用户确认时，模型调用 `ask_user_question`，提供一个问题、提问原因、零至四个选项。用户可自由回答。
4. 内核在执行这一批任何画布操作前检查提问。存在提问时保存 `agentState.pendingQuestion` 和原始工具调用；同批其他操作返回 `awaiting_user`，明确它们尚未执行。运行立即返回等待状态，不维持后台模型循环、不使用超时自动批准。
5. 页面刷新或切换会话后，提问卡片由保存的会话恢复。用户点击“回答并继续”或在输入框回答时，先写回原 `toolCallId` 对应的工具结果，清除待回答状态，再带着已有协议记录和原始附件继续推理。当前输入中的附件会合并进去。
6. 取消提问写回 `user_cancelled`，保留已完成结果，不调用模型、不执行待定操作。已经处理的问题不能再次写回答案。

普通文字回复仍然可以用于直接回答和解释；必要的等待应走结构化提问。提问时机由模型根据协作指令判断，工具调用一旦提出，暂停由运行时代码保证。该机制不能保证所有模型在所有歧义请求上都作出理想判断，需要持续补充真实模型评测。

## 普通对话与响应延迟

独立问候、致谢和能力介绍通过共享 `conversation.json` 精确匹配进入轻量对话；混合创作请求、带引用/Skill 的消息和待回答问题保留完整 Agent 流程。轻量对话仍由当前模型回答，经 SDK 执行一次无工具的请求，仅携带有限的近期聊天文本，跳过工具历史、画布详情和摘要生成，关闭额外推理并限制输出长度。不会自动恢复媒体生成，也不会让旧计划影响本轮完成状态。旧计划保存在会话中，但闲聊时不展示计划和待生成提示。

模型任务的公开文字增量经后端快照同步到回复中；长历史摘要不作为公开回复输出。界面显示实际的发送、引用读取、回复或工具活动，普通消息不再统一显示“准备资料”和“分析下一步”。新消息不会自动恢复旧媒体任务；显式继续、生成选择和 SDK 待答恢复仍按既有规则执行。此改动减少应用侧额外请求与等待，不保证中转服务或模型的首字延迟。

上下文预算分别估算文字与图片，不把图片 Base64 的传输字节数当作文本 token。每张图片暂按 3000 token 预留视觉预算，仅用于上下文规划，不代表各模型的实际计费。首轮参考图直接交给模型理解，不预先逐张摘要。本轮原始文字与参考图始终保留；超过预算时仅摘要历史对话或本轮已完成且工具调用与结果成对的记录。摘要输入排除图片像素及不透明推理数据；全部摘要成功且满足预算后才替换记录。若本轮必要输入本身过长，明确提示减少素材或 Skill，不自动改写原始要求。回归测试覆盖首轮八图、长历史、完整与不完整工具记录以及摘要失败时保留原始记录。

浏览器显示用量的估算使用独立 Web Worker；Worker 安装消息处理后发送 `ready`，界面收到后才传输完整协议历史。等待期间只保留最新画布上下文，取消或已卸载的面板不再传输历史。同一历史在 Worker 中保留，后续只发送变化的上下文；历史或摘要变化时释放旧 Worker。未知结果、失败与尚未估算分别处理，不把失败显示为零用量。首次有效传输仍需结构化复制完整历史，这不代表首开性能已经通过验收。

引用采用 ID：浏览器向 Agent/画布工具后端仅传节点或附件的 ID 与来源，后端在当前用户项目和会话内解析，拒绝不存在的引用。原生 Agent 不再让浏览器预下载图片并回传 Base64；执行记忆保存素材地址，公开图片直接以 URL 发送，受保护的私有素材在模型请求边界鉴权并编码为视觉输入，不作为文字进入上下文估算或摘要。URL 与 Base64 只是传输形式，图片仍有视觉 token 成本。

内置 Agent 和 Codex 默认只接收最多 40 个节点的轻量索引、总量、选中 ID、已确认约束和当前计划；完整正文、媒体地址、连线全集、模型能力、已完成任务历史和内部运行状态不再随每次提示词重复发送。节点正文由 `get_node` 按 ID 读取，文本只返回一份 `text`；附件正文由 `get_reference` 读取，连线由关联节点工具读取，生成能力由 `get_generation_config` 读取。分页检索仍支持按正文查找，但只返回索引。写入节点、保存模板和查询任务只返回必要 ID、版本或状态，避免重复回显全文；Codex 的界面同步状态和审核指纹不进入模型工具回包。数据保留在原有存储，按需读取不会改变原始素材或执行权限。


## 按交付目标选择媒体和参数

Agent 输入区及画布库的 Agent 入口不再提供固定的图片、视频参数按钮；会话配置只保存运行偏好和 Skill。媒体类型与每次生成参数由 Agent 根据需求判断：平面广告只走图片流程；文字或已有素材足够的宣传视频直接走视频流程；短剧按实际依赖组合角色/场景参考图和视频，复用已有素材。

`generation.capabilities` 和 `get_generation_config` 提供当前模型支持的图片比例、画质、分辨率、精确尺寸能力，以及视频尺寸、清晰度、时长和声音能力。图片工具支持逐次传入 `size`、`quality`、`resolution`、`count`，视频工具支持 `size`、`resolution`、`seconds`、`generateAudio`。参考图与成片可以使用不同参数；省略参数时才使用默认值，默认值不代表用户约束。不支持的画质、分辨率和视频尺寸，以及错误的图片尺寸格式，在创建节点前返回错误和支持列表；像素尺寸沿用现有图片适配器的转换规则。

视频能力由服务端当前启用的模型契约提供，不信任浏览器传入的声音声明。`audioControl` 的 `always` 表示固定原生有声（无需音频开关字段），`toggle` 表示可开关，`none` 表示不支持，`unknown` / `contractConfigured=false` 表示缺少可用契约，不能推断为不支持声音。原生有声视频无需创建独立音频节点。内置 Agent 与 Codex 共用 `list_video_models` 查询服务端可用模型及能力，用户指定或明确委托后通过 `set_video_model` 切换当前画布选择，保存到 `agent_config.videoModel` 并同步界面。切换不修改管理员配置、已有节点或已提交任务；后续视频使用新模型和新能力。

旧的项目媒体默认值不再控制 Agent 生成。已创建节点保留自己的参数，仍可在节点设置中手动修改。自动生成开关只控制是否提交媒体任务，不决定生成哪一种媒体。

脚本工作区创建素材或镜头节点时，单次工具和工作流步骤都使用 `scriptNodeId`，并指定 `assetId` 或 `shotId`；节点创建时同步保存素材/镜头关联及媒体提示词。已有节点通过 `update_script_node` 核对后关联复用。素材节点在提交生成前保存并显示在脚本左侧，作为输入连入脚本；生成中可跳转至画布节点。替换素材时同步维护对应镜头的输入连线。脚本内容、提示词或引用素材变化后，保留已有成品并分别标记图片/视频为待更新；旧成品不自动确认新脚本、不自动重提生成，也不参与成片合并。脚本工作区提供镜头预览、重新关联、解除关联和明确重试入口，批量执行前汇总新增、复用与待更新任务并检查提示词、素材、模型及参考图限制。重新整理脚本必须保留已有素材/镜头编号及绑定，模型丢失关联时拒绝替换。复制脚本重映射所有已复制节点引用，未复制的外部绑定清空；删除节点同步解除脚本引用。镜头媒体作为输出，批量执行等待素材完成。新镜头任务提交前要求脚本已确认、该镜头引用的素材已有成功图片，并自动将图片作为生成参考。条件不足时不分配新任务 ID、不提交媒体；已有完成或进行中的任务继续复用，失败重试遵循原有确认规则。

静态广告不会加载影视制作流程；共享协作指令、Skill 与工具描述统一采用最少必要提问。已提供的条件、已接受的限制和已授权的步骤继续沿用；“开始吧”“直接生成”在当前目标与范围内直接推进。未指定的图片数量默认一张，比例、单片段时长、声音与画质按用途和当前合法配置选择，简短说明采用值，不把默认决定冒充用户确认。主体或硬性条件确实无法确定、目标冲突、明显增加成本或超出范围时才提问，同阶段必要缺口合并一次。技术错误与配置通知直接说明具体阻塞和操作方法，不包装成问题卡或要求回答“配置好了”；内置 Agent 生成失败后可用 `finish_task`（`status=error`）说明阻塞并结束本轮，运行与轨迹保留失败状态，不会伪装完成或被替换成笼统的继续提示。真实的系列提示词审核、删除确认、生成暂缓和取消边界继续由原执行机制保护；沉默和超时不代表同意。工具 Schema 仍要求图片显式提供 size/count，视频显式提供 size/seconds/generateAudio；漏传会拒绝调用并要求模型补齐，而不是要求用户逐项确认。提问时机依然由模型判断，提示词回归不能代替真实模型效果评测。

参考素材地址优先使用显式 `IMAGE_BASE_URL`，留空时使用当前 HTTP 请求的网站地址，HTTPS 和转发 Host 仅信任现有代理规则。内置 Agent 与 Codex 工具提交时由服务端注入地址，后台媒体任务继续携带，不接受浏览器 JSON 指定该内部字段。签名校验使本站暂存文件不依赖固定素材域名即可被识别；文件权限、有效期与内容校验保持执行。URL-only 模型仍要求上游可访问站点，本机/内网地址会报告可访问性限制，不再误报必须配置覆盖项。

普通分镜默认每个结构化镜头一张单幅画面，绑定 `scriptNodeId` 与 `shotId`；镜头直接保存在脚本 `shots` 中，不额外创建重复文本节点。只有用户明确要求宫格、拼图或多面板时才使用网格与面板转译规则，普通“分镜”或 `storyboard` 名称不能作为多面板依据。单幅图片只描绘可见状态，动作时序与逐字对白保存在脚本及视频提示词中，不写进图片画面。

用户明确委托自主创作并完整制作且没有要求先审核脚本时，Agent 先保存、重新读取并核对脚本，再将 `get_node` 返回的 `confirmationFingerprint` 原样传给 `confirm_script_node` 单独确认制作状态，继续已授权步骤。确认工具不重传正文；读取后或保存合并期间内容变化时拒绝旧确认并要求重新核对。用户要求审核、暂不生成或没有授权制作时仍等待真实确认。修改内容仍使确认失效，不能在同一次修改里覆盖失效；制作状态确认不会写入人工质量验收记录。

脚本 `get_node` 的 `node.production` 一次返回按镜头顺序排列的图片、视频、任务状态、过期标记及已有实测媒体属性，附当前成片状态；交付核对优先使用这份摘要，只有正文缺失、状态变化或冲突时再读取具体媒体节点。`plannedDurationSeconds` 是计划时长，只有全部当前有效视频都具备实测时长时才返回 `actualDurationMS`；缺失音轨信息保持未知。`canMerge` 仅表示镜头技术可用，不代表内容验收通过，质量状态只读取当前视频对应的已有人工记录。计划在阶段或关键状态变化时更新，不围绕每次只读调用重复更新。

## 分镜合并成片

多镜头制作完成后，Agent 在结束任务前调用 `merge_script_videos`，只需指定脚本节点；也可在聊天中要求“合并这份脚本的分镜视频”。按脚本 `shots` 的顺序读取关联视频，全部镜头都须可用，不跳过缺失或失败片段，也不重新调用视频生成模型。用户明确只要独立片段时不自动合并。是否调用由 Agent 根据任务目标判断，只有工具真实成功才可声称成片已交付。

服务端使用 FFmpeg 合并 MP4，按第一段画幅统一尺寸，最长边不超过 1920，保持比例并补边；保留各段原声，缺音轨的片段填充静音。输出独立成片视频节点，保留原分镜及来源连线，成片可沿用视频节点预览和下载。相同分镜来源和顺序复用已有成片，来源或顺序变化后可重新合并。合并前后及最终保存时核对来源，避免将过期成片写入画布；已上传文件仍保存在当前用户存储中。

合并复用后台 Agent 的异步执行、停止与保存流程，关页不取消后台工作，停止 Agent 会终止本地合并。源素材和输出均按当前用户校验权限，远程地址通过现有安全下载客户端获取，不把网络地址传给 FFmpeg。支持 2–200 段、单段最多 100 MiB、总输入和输出各最多 1 GiB、成片最多 30 分钟，单次处理超时 15 分钟。源码环境须安装 `ffmpeg` 和 `ffprobe`，Docker 镜像已包含；缺少依赖时明确报错并保留原分镜。

## 执行边界

Agent 运行时画布仍可浏览、拖动和编辑。前端把未保存修改按节点 ID 和字段合并到后台快照，版本冲突后重新读取并重放本地修改；后端 worker 只合并自己实际修改的字段，并保留用户并发修改、删除和新建的节点。会话执行记录由 worker 管理，浏览器编辑不得覆盖运行状态。同一画布仍只允许一个 Agent 运行，整幅画布的清空或删除需先停止运行。撤销历史同步合并后台结果，避免撤销用户操作时移除 Agent 新结果。

内置 Agent 在模型返回、工具执行前和结果提交时同步最新画布。节点内容或连线变化会使旧批次失效，返回可恢复的 `canvas_changed`，重新读取和规划；拖动位置、缩放、展示进度及媒体自动补充的文件大小、用时和缩略图不使内容判断失效；如果 Agent 正在排列或分组节点，则用户新调整的位置会使旧布局操作失效。`canvas_changed` 只表明状态与执行快照不一致，不能证明变化来自用户；工具和模型不得直接归因为“用户改动”，应先核对节点、输入和已有任务，以实际结果说明是否写回，仅在确需用户决定覆盖或重新付费生成时提问。执行过程显示“已调整”，不会把正常编辑显示成红色故障。连续四次模型判断过期时，保存进度并等待继续，避免不停消耗请求。工具里缺失的节点引用同样触发重新判断，不向用户索要内部 ID。

媒体提交前、生成返回后及最终乐观锁合并时再次核对目标和上游依赖。目标被删时不恢复节点、不创建额外输出；目标或依赖内容变化时不自动写回旧结果，原任务仍可通过任务记录核对，并记录为未应用任务以防自动重复提交。无关节点修改不丢弃当前有效生成结果，但下一批操作需要基于新画布判断。Agent 删除节点时若用户同时修改了节点，保留用户版本；删除确认绑定节点内容指纹，确认期间内容变化需重新确认。模型负责判断能否继续无关步骤，缺少必需素材或存在歧义时使用现有选项和自由输入提问。

任务用时累计同一请求中澄清问题前后的处理时间，等待用户回答时暂停；新请求单独计时。运行中直接展示最近三项真实工具操作，更早记录可展开查看。

- 所有工具参数在执行前统一校验，计划步骤等嵌套对象也拒绝未知字段、无效类型、重复 ID 和越界数量。
- 内置 Agent 的工具批次顺序执行；普通操作失败后，后续操作返回 `dependency_failed`；画布变化时返回 `canvas_changed`，旧批次后续操作不继续执行，下一次模型判断使用最新画布。
- `run_canvas_workflow` 内部按依赖调度，最多并行生成 4 个就绪媒体节点。画布、任务 ID、会话和执行记录由 worker 串行更新，只有媒体请求并行。独立节点完成后立即释放并发槽位，依赖素材未完成时不会启动下游；发现失败或画布变化后停止提交新任务，收集并保存已经提交的其他结果。模型通过 `create_canvas_workflow` 批量建图，再调用工作流执行工具获得并行能力，连续调用多个单图工具仍按工具批次顺序执行。
- 同批交付可以通过 `groupTitle` 自动分组，已有模板系列默认按模板名称分组，原始素材不加入结果组。前端工具栏、键盘、右键及 Agent 删除组时均连同成员、批量子结果和关联连线删除，组外来源及下游节点保留。删除确认包含组内数量并绑定成员内容指纹；撤销沿用画布历史恢复整组。删除生成中的组不自动恢复节点，已提交媒体任务仍遵循其任务生命周期。
- 来源节点用 `sourceNodeIds` 建立来源到结果的连线，本批依赖使用 `dependsOn`，独立图片不得为了排序而串联。执行下游前读取实际成功媒体作为生成输入；多张输出继承相同的来源连线与分组。聊天附件继续通过 `attachmentIds` 引用，不自动转换为画布节点。两种 Agent 引擎共用这些工具描述和内置规则；自然语言任务是否正确拆成依赖仍由模型判断。
- 每批执行前记录完整工具调用及 `execution_not_started` 占位结果；进入工具前记录 `execution_unknown`，取得真实结果后立即替换该调用的记录。每次检查点都保留 Chat/Responses 的调用与结果配对，已经成功的节点、任务 ID 和计划不会因同批后续工具中断而丢失。
- 停止时立即结束 Agent 对当前工具的等待，保留已取得的结果；尚未开始的操作不执行，已开始但尚未返回的操作明确标为结果未知。已提交的媒体任务继续使用画布原有生命周期，停止 Agent 不等于取消媒体生成。迟到的工具响应不再更新已停止运行的会话记录。
- 页面刷新只重新订阅后台快照，正在执行的后端循环继续运行。服务重启或用户主动停止后，用户选择继续，模型根据当前画布、真实工具结果及未知状态重新判断；不能假定未知操作未发生。媒体恢复复用已保存的节点和任务 ID。
- 确认问题不授予笼统权限：答案进入模型上下文供判断。内置 Agent 删除节点会单独暂停，要求用户输入“确认删除”；外部 MCP 授权和自动生成设置仍由各自执行边界处理。
- `update_plan` 是模型记录的任务进度，不能替代真实媒体任务状态。`loading` 仅代表任务已提交，完成步骤应以工具结果为依据。
- 用户授权和实际工具结果优先；附件、节点正文及工具文本中的指令不能成为新的操作授权。

## Codex 通道

Codex 的 `update_plan` 工具更新同一份会话计划，`ask_user_question` 使用既有的用户输入对话框，等待真实回答再返回工具结果。取消和断开连接仍使用现有 AbortSignal 生命周期。

Codex 的运行恢复由其 App Server 会话负责；本页持久化提问卡片是内置 Agent 的能力，不能据此声称 Codex 本地请求在刷新后自动重放。外部 MCP 不允许调用仅属于当前 Agent 运行的计划、提问和 Skill 文件读取工具。取消任一种 Codex 提问后，本轮后续画布写操作和本地命令/文件审批均拒绝；新一轮用户请求可正常继续。轮次结束即中止未完成的审批，迟到回答不能发送给过期轮次。

Codex 将用户输入、提问答案、画布工具调用/结果及最终回复写入共享会话历史。工具开始前写入结果未知的配对记录，取得结果后替换；中断时保留已知结果。切回内置 Agent 后废弃旧 Codex 线程绑定，下次 Codex 新建线程时接收会话历史，避免遗漏另一引擎的后续进展。复用同一 Codex 线程时不重复注入历史。模型列表分页检测重复游标及页数上限。

## 会话增量保存

局部画布保存使用 `agent_session_updates: [{ id, changes }]` 更新已存在会话的 `title`、`engine` 与 `updatedAt`，仅接受字符串，`engine` 限定为 `native` 或 `codex`。只有这三个字段变化时，浏览器不提交 `messages` 或 `protocolMessages`；正文变化、新建会话、字段清除或其他会话字段变化仍提交完整会话正文。未改变的会话正文继续由服务端保留。

每个更新必须携带 `agent_session_summaries` 中的原 `content_hash`；画布 revision 已刷新也不能覆盖哈希过期的会话。同一会话不能同时提交元数据更新、完整正文或删除，重复 ID、未知会话、非法字段和运行期间的元数据更新均拒绝。更新只属于传输协议，不进入持久化文档或改变数据库格式；服务端执行字段与未知会话字段保留。

版本校验与局部合并共用一次会话拆解和元数据读取，校验写入、删除及元数据更新的原内容哈希后，再构造合并结果；不为版本校验重复拆解同一份完整历史。任一目标会话缺失或过期的原哈希都会拒绝整个混合保存，未修改的会话不要求更新确认值。只读保存仍验证原会话元数据并保留原始字节。

元数据更新通过上述校验并从服务端正文合并后，不再重复解码其消息与协议。浏览器提交完整正文时，服务端通过 `json.RawMessage` 保留字段值，只将 `toolReceipts` 与 `contextUsage` 恢复为原服务端值或移除伪造值，避免将 JSON 大整数及高精度小数转换为浮点数。混合元数据与正文保存继续执行相同保护；正文未重建时不重复编码会话数组。

成功回执返回新摘要与已接受的 `agent_session_updates`，省略对应的长会话正文。前端先核对回执与本次提交的更新完全匹配，再用本次提交的完整会话恢复正文并执行既有三方合并，保留保存期间新增的消息及编辑。缺失、重复或不匹配的回执明确报错，不能把省略正文解释为聊天被清空。

历史分块读取直接解码存储 JSON 中的 Base64 数据，继续校验非空、64 KiB 上限、分块哈希、完整长度和会话摘要。拼接先保留逐块验证后的数据并检查累计长度，超过清单声明即拒绝；总长度完全一致后一次分配输出，不依赖清单预分配大缓冲区，也不边读边扩容复制完整正文。完整读取当前版本的工作区后，仅在本次操作内保留已验证引用与会话/旧消息的内容指纹；归档时只有两份指纹均未变化才复用原引用，省去再次读取全部分块。正文变化继续正常归档，旧格式继续在成功保存时升级。验证信息不持久化，也不跨请求复用。

数据库返回的 JSON 字符串直接交给解码器，不再先转为字节数组再转回字符串；数值继续使用 `json.Number` 保留精度，仍拒绝损坏内容和尾随的第二份 JSON。该调整只减少输入复制，不改变数据库查询、CAS 基线、分块完整性检查或持久化格式；当前会话正文与工作区根仍整体读取，不能据此认定首开性能达标。

画布库以 `GET /api/canvas?view=projects` 读取项目摘要和活动项目 ID。服务端核对当前账号的工作区清单及活动指针，首次打开沿用默认画布初始化。现有库内管理操作可使用同一视图取得更新后的摘要和活动标记，仍按项目 revision 和已有保存流程提交。点击卡片直接导航，编辑器按目标项目加载所需会话。导出按项目请求完整文档及聊天记录。

编辑器首开和通过链接激活项目使用 `history=editor`。关闭 Agent 的已索引项目先读取会话摘要及活动 ID。后台正在执行或收尾、待提交请求、缺少会话索引以及需要修复的历史仍按原规则读取正文。用户打开面板时请求当前会话视图，正文返回前保留原选择并显示加载或重试。版本落后的响应重读，离开画布取消请求，同版本正文按当前本地修改合并。正文未加载时的画布保存仍携带会话目录及原活动 ID。

编辑器查询分享状态时，只读取账号所属工作区清单，并确认请求项目仍在清单中；不加载任意项目的聊天分块，也不读取或更新活动项目。未知账号或项目返回不存在，孤立分享索引不能返回有效状态。创建/撤销分享和公开文档读取继续执行完整工作区流程，状态查询成功不代表损坏的正文可公开读取；GET 不负责初始化工作区、迁移或修复历史。

从指定项目链接打开编辑器时，直接通过现有 activate 操作读取目标画布，不先下载上次活动项目。切换接口复用按项目读取逻辑：活动视图只载入当前及运行所属会话，完整视图只载入目标项目全部会话；目标正文读成功后才写活动项目指针，不重写工作区根或聊天。HTTP 切换与普通读取共用 Agent 执行锁及快照协调，服务中断/孤立运行修复仍保留未加载会话。浏览器读取可取消，迟到响应不能回写已离开的页面；文档应用继续等待模型契约。当前项目正文、根清单、必要修复和组件加载仍有开销，不代表端到端首开已验收。

局部保存回执也可复用本次读取已验证的会话摘要，但必须再次核对完整会话内容指纹。无需返回正文时不再拆解完整会话；显式请求的正文以及未确认版本的当前/运行会话继续返回。正文变化时重新计算摘要，返回的目录与私有验证信息隔离。

发布仍使用工作区 CAS 与同一事务中的历史回收。另一写入方在本次读取后替换并回收旧分块时，旧根不能发布；写入重读最新工作区，重新验证分块并重建引用后再尝试，不能从旧验证信息恢复已被回收的历史。
