# 视频生成契约

视频生成请求发送到配置的中转地址（通常是 NewAPI），但 NewAPI 只是网关，不是视频协议。本项目按模型契约明确选择接口协议，不根据模型名称或厂家猜测协议；NewAPI 再根据模型和渠道配置完成实际上游路由。

最新版官方 QuantumNous/new-api 的具体核验版本、四个已配置模型的字段差异及可导入样例见 [New API 视频接入核验](newapi-video-compatibility.md)。

同一接口协议的模型可以共用一条契约，通过 `model_profiles` 分别配置完整的参数范围、生成模式和条件规则。模型未单独配置时使用顶层通用能力；请求字段、传输、轮询和下载仍共用。编辑、预览和实际提交都按所选模型解析，任务保存解析后的能力快照。实例见 [Dramaya Grok 视频契约](dramaya-grok-video.md)。

## 素材用途

- **首帧（`image`）**：指定开场画面，提示词描述后续动作，不保证人物全程不变。
- **尾帧（`last_frame`）**：指定收尾画面，中间动作由提示词引导，动作跨度需符合视频时长。
- **参考图（`reference_images`）**：提供人物、场景和物品的外观依据，不限定开场构图，也不保证跨镜头完全一致。
- **声音参考（`reference_audios`）**：用于指定声音，台词通常写在提示词中；不等同于录音驱动口型，也不是背景音乐输入。
- **关键帧（`keyframes`）**：指定中间时刻的画面，控制动作顺序与节奏；当前通用创作界面未提供此输入。
- **视频输入**：可用于编辑、延长或参考动作与运镜，具体用途由模型定义；音频驱动视频则要求模型明确支持按录音生成表演或口型。

以上括号内为示例上游字段，实际字段、素材数量及组合限制以模型契约为准；Grok 的预设 `voice_id` 也不等同于本项目的参考音频文件上传。

## 职责边界

- 全局模型设置决定用户可见、可选择的视频模型 ID。
- 用户创作偏好只能在全局已启用的视频模型中选择默认模型。
- 视频模型契约按模型 ID 声明参数面板、生成模式、素材约束、请求字段映射、厂家传输驱动、轮询状态和产物获取方式。
- 使用 NewAPI 时由其负责 API Key、渠道、模型映射、厂家选择和故障转移；使用其他上游时仍可由内置厂家驱动或自定义异步协议完成传输。
- 契约不会向全局模型列表注入模型。一个契约可以包含多个匹配规则，但只有全局模型设置中的模型才会出现在创作页面。

## 请求流程

创作台或无限画布向 `/api/creation-tasks/video-generations` 提交模型 ID 和通用参数。服务端必须先找到启用的匹配契约；没有匹配契约时直接拒绝任务，不尝试厂家推断或通用兜底。

服务端使用契约完成以下处理：

1. 校验画幅、时长、清晰度、音频、水印和参考素材。
2. 根据实际素材推断文生视频、图生视频或参考素材生视频模式。
3. 将通用参数映射为契约声明的请求字段。
4. 原样透传模型 ID，并按契约的接口协议创建任务。
5. 按同一接口协议和契约声明的任务 ID、状态、错误及结果 JSON 路径轮询任务。

任务创建时会把当时匹配到的完整契约保存为任务快照。排队或执行期间即使管理员修改、禁用或删除契约，已创建任务仍使用原快照完成请求构造和响应解析。

## 模型匹配

模型匹配不区分大小写，并忽略首尾空格。规则支持精确模型 ID 和 `*` 通配符，例如 `minimax-*`、`minimax-h3-*`。

多个规则同时匹配时按以下顺序选择：

1. 精确匹配优先于所有通配符。
2. 固定字符更多的通配符优先。
3. 固定字符相同时，通配符更少的规则优先。
4. 前三项相同时，契约 `priority` 数值更高的规则优先。

例如同时存在 `minimax-*` 和 `minimax-h3-768p` 时，`minimax-h3-768p` 必然使用精确契约，和两份契约的 `priority` 无关。两条会重叠且前三项完全相同的通配规则必须设置不同优先级，否则管理端拒绝保存，避免结果依赖录入顺序。

## 传输

当前契约版本为 v4，支持以下视频驱动：`openai-videos`、`xai-videos`、`gemini-veo`、`vertex-veo`、`dashscope-video`、`volcengine-video`、`kling-video`、`minimax-video`、`vidu-video`、`kie-video`、`apimart-video`、`custom-video`。

厂家驱动继续保留，不把系统绑定到 NewAPI。内置驱动提供默认创建和查询入口；契约也可以使用 `transport.create_path` 和包含 `{task_id}` 的 `transport.query_path` 覆盖入口。按上游公开接口匹配驱动，不按模型厂商匹配：网关提供 OpenAI Videos 兼容接口时可使用 `openai-videos`，普通 JSON、嵌套字段或 multipart 本身不要求使用自定义协议。`custom-video` 用于内置协议无法表达的独立异步任务接口；需要特殊签名、加密或响应封装时仍应增加独立厂家驱动。

除 Kling 原生入口外，当前 NewAPI 厂家驱动都从 `POST /v1/videos` 创建并从 `GET /v1/videos/{task_id}` 查询。驱动仍需分开声明，因为各厂家读取的请求参数不同，例如 Gemini/Vertex、火山和万相会从 `metadata` 中读取厂家参数。请求字段映射支持 `metadata.durationSeconds` 这类嵌套路径。

- `xai-videos` 使用 NewAPI 的 `/v1/videos` 入口；最新版官方 NewAPI 已有 xAI 任务插件，仍需启用插件并正确配置模型与渠道。
- `volcengine-video` 使用 NewAPI 的 Doubao 任务插件，驱动把首尾帧和参考素材转换为带类型与角色的 `metadata.content`，只支持 URL 素材。`ark-seedance` 用于直连方舟原生入口，两者不能混用。
- `kling-video` 使用 `/kling/v1/videos/text2video` 或 `/kling/v1/videos/image2video` 原生入口。
- `kie-video` 和 `apimart-video` 仍调用 NewAPI 的 `/v1/videos`，由其 Sora 任务适配器转换为聚合平台协议。

模型 ID 始终原样传输。协议完全由匹配到的契约决定，不自动选择、不做厂家推断，也没有无契约兜底。NewAPI 只是默认部署中常用的中转实现，并不是契约运行所必需的协议。

## 产物获取

契约显式选择最终视频的获取方式：

- `response_url`：从轮询响应的 `result_fields` 读取视频地址，适合厂家 CDN 或聚合平台返回地址。
- `task_content`：按 `artifact.content_path` 和任务 ID 获取内容，例如 `/v1/videos/{task_id}/content`，适合 NewAPI 或其他内容代理。

`artifact.auth` 为 `none` 时不会向视频地址发送中转 Key。设置为 `relay` 时，仅允许向中转自身或 `artifact.allowed_hosts` 明确允许的域名发送 Bearer Key，避免结果地址被篡改后泄露凭据。公开结果地址还会经过公网地址与 SSRF 校验。

生成完成后需要下载到本地的视频，会在保存期间继续显示处理中；保存失败显示“视频已生成，保存失败”，与上游生成失败区分。服务端保留原任务 ID、下载地址和所选连接标识，不在任务中保存 API Key，也不向前端返回私有下载配置。

有恢复信息的失败任务会返回 `can_recover_video: true`。任务所有者可调用 `POST /api/creation-tasks/{本地任务ID}/video-content`，或在创作台点击“重试保存视频”。该操作使用原连接获取已有成品，不提交新的生成请求；原连接地址发生变化时拒绝下载。保存成功后更新同一条任务，后续重复调用直接返回已保存的结果。下载网关仍报错时保留恢复信息，修复网关后可继续重试。

## 发布与调试

编辑已有契约可以先保存草稿；草稿不会进入运行时，也不会影响新任务。发布时系统先校验完整契约集合，再一次性替换运行时索引。每个契约保留最近 8 个已发布版本，回滚会基于历史内容发布一个新的修订，不覆盖审计记录。

管理页的请求与响应模拟只执行字段映射、路径选择、任务 ID 提取、状态归一、进度和结果解析，不访问上游，也不会产生视频费用。任务创建时仍保存完整契约快照，已经进入队列的任务不受后续发布和回滚影响。

NewAPI 根据原样传入的模型 ID 选择渠道；本项目的驱动决定请求结构和入口，模型契约决定具体能力及字段路径。驱动不会向模型列表注入模型，也不会替代 NewAPI 的渠道配置。

NewAPI 的 `/v1/videos` 对外状态为 `unknown`、`queued`、`in_progress`、`completed`、`failed`。契约分别声明排队、处理中、成功和失败原始状态；未匹配的值统一视为 `unknown` 并继续轮询。平台任务将 `queued` 保持为排队中，将 `in_progress` 和 `unknown` 映射为处理中，并保留 `upstream_status` 与 `progress` 供任务界面展示和排查。旧契约缺少新增字段时会自动采用 `queued`、`in_progress` 和 `progress` 路径。

进度条需要契约明确声明查询响应中的进度路径。例如接口返回 `{"progress":9}` 时，设置 `polling.progress_fields` 为 `["progress"]`；嵌套响应使用 `["data.progress"]`。显式空数组 `[]` 表示不读取进度，即使上游有百分比，界面也只能显示等待状态。修改契约只影响新提交任务，已经提交的任务继续使用原契约快照。

契约可以把本地参考素材声明为：

- `url`：参考素材必须是上游可访问的 HTTP 或 HTTPS URL。
- `multipart`：本地素材使用契约声明的文件字段上传；可配置字段是否可重复，以及是否允许和外部 URL 混用。

请求体只包含 `model`、`prompt` 和契约明确映射出的字段。客户端提交的厂家、渠道或其他未声明字段不会透传。

## 管理要求

视频模型契约在设置页统一管理，支持手动编辑、参数面板预览、原始 JSON 查看、导入导出，以及从文档或网页链接分析出待审核 JSON。

文档和链接生成共用协议匹配流程，优先选择有文档证据的内置协议。生成结果如果使用通用字段映射和 `/v1/videos`、`/v1/videos/{task_id}` 创建/查询路径，会将 `custom-video` 归入行为等价的 `openai-videos` 并使用默认路径，保留原有字段映射、模型能力、轮询及下载配置。其他独立路径或专用转换不会仅凭模型名自动改换驱动。审核列表展示协议和路径来源；已有契约与直接 JSON 导入不会被此流程改写。

新增模型时：

1. 在全局模型设置中添加 NewAPI 实际可用的模型 ID。
2. 根据实际中转或厂家暴露的请求和响应协议创建或导入 v4 契约。
3. 在预览中确认参数面板、生成模式和素材限制。
4. 保存并启用契约后再提交测试任务。

文档分析由受控 Agent 执行，分析模型需要支持工具调用。Agent 先调用 `inspect_protocols` 获取代码中的真实协议能力，再根据证据调用 `read_documents` 补读候选页面，使用 `validate_contracts` 校验契约与原文引据、干跑各模型各模式的代表性输入，并调用实际请求映射与专用转换构造请求预览。`finish` 只能返回最新验证成功的草稿；补读新文档或校验失败会使之前的验证结果失效。最多 12 个分析步骤、24 个相关页面、3 次配置校验，总时限 8 分钟，支持停止分析。

引据缺失或无法表达的要求仍会标记待确认；本地校验不代表实测供应商，也不覆盖全部参数组合。AutoDL 完整请求依赖线路工作流配置，单独的文档草稿保持待确认。Agent 只能使用固定文档工具，不能执行任意 shell 命令、自动发布或提交计费视频任务。

页面默认只显示当前步骤和耗时。“查看执行详情”默认收起，展开后可查看实际工具名、调用参数、返回结果以及模型公开回复；不展示内部推理。详情对常见凭证和 URL 查询参数做脱敏，并限制展示长度；仅保存在当前页面内存，不写入操作日志。停止、失败和进入审核页后仍可回看，重新生成时清空。

链接分析会保留入口正文，并按需补充相关页面；入口已经完整时可以不补读。模型输出中的素材模式或数量约束有冲突时会反馈给模型修正，不通过删除素材约束来接受结果。

文档生成的草稿通过 `POST /api/admin/video-model-contracts/batch` 一次性新增并发布。名称或模型冲突会使整批操作失败，已有契约及其待发布草稿保持原样。生成警告和发布错误会保留在审核窗口中。文件形式的 JSON 导入仍有独立的同名更新确认流程。启用插件生成后，插件源码也会先在隔离环境中用模拟数据干跑；通过后才开放下载，不会请求上游。
