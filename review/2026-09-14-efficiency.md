# 2026-09-14 效率与正确性审查

本轮对当前工作区继续进行跨模块审查，保留开始时已有的 SSO、界面统一和 F01-F10 等未提交改动。以下只记录本轮新增修复，代码未提交或发布。

## 发现与修复

| 编号 | 类型 | 问题与修复 |
| --- | --- | --- |
| E01 | 性能 | 画布批次可见性对每个子节点扫描全部节点。改为一次建立节点索引，筛选复杂度由 O(N²) 降为 O(N)，保留折叠、展开、动画和孤立子节点语义。 |
| E02 | 性能 | 拖动、缩放节点时任务状态未变也替换全局快照并通知订阅者。相同任务保留对象引用，只在队列实际变化时通知和更新清理计时器。 |
| E03 | 性能 | 内嵌静态资源没有有效的缓存策略。带内容哈希的 Vite 构建资源设置一年 immutable 缓存；入口 HTML 和非版本化资源要求重新验证，缺失文件不设置长期缓存。 |
| E04 | 性能 | 聊天历史先解码所有图片再截取最新 14 张。改为反向选择有效图片，只解码保留内容，最后恢复原有顺序。 |
| E05 | 性能 | `util.Clean` 使用 `fmt.Sprint` 复制原生字符串，包括大型 base64 数据。原生字符串直接裁剪，其他值保持既有格式化行为。 |
| E06 | 性能 | 用户用量统计一次加载整个日期范围日志，并发缓存失效重复聚合，旧日期缓存持续累积。改为每批最多 1000 条的固定快照分页；合并并发缓存填充，保留日志写入并发，移除过期缓存。 |
| E07 | 性能 | 日志深页的 OR 游标条件重复扫描同日较新记录。拆成当前日和更早日期两个有界索引查询，保持日期排序及快照隔离。 |
| E08 | P2 | 审计捕获吞掉请求体读取错误，不完整请求可能继续解码执行。重放已读内容时保留原读取错误和 Close 行为。 |
| E09 | P2 | 已知超出接口限制的请求，在返回 413 前仍等待审计读取上传数据。审计跳过已知过大的正文，交给路由直接拒绝。 |
| E10 | P2 | 素材初始列表晚到，覆盖加载期间成功新增、修改或删除的结果。对初始快照按顺序应用期间已确认的变更。 |
| E11 | P2 | 素材选择器关闭重开后，旧排队写入借用新周期继续执行。排队时绑定原生命周期，失效写入不再派发或更新新列表。 |
| E12 | 性能 | 批量素材文件清理逐项重新读取所有画布。仅在同一次清理操作中共享引用读取并去重文件删除，保留服务端逐项引用保护。 |
| E13 | P2 | 批量删除中途失败，已删记录的文件未被清理，后续项也不再处理。继续逐项执行，只清理已成功删除的记录，保留失败选择并显示实际成功和失败数量。 |

实现主要位于 `web/src/app/canvas/canvas-batches.ts`、`web/src/store/canvas-task-queue.ts`、`web/src/lib/use-my-assets.ts`、`web/src/app/assets/page.tsx`，以及 `internal/web/web.go`、`internal/protocol/core.go`、`internal/util/json.go`、`internal/httpapi/audit.go`、`internal/service/log.go` 和 `internal/storage/storage.go`。
